### 保底防护：无论有没有攻击都要付的一笔

保底防护是实例的防御能力下限，预付费，支持按月或按年购买，年付通常有折扣，具体以购买页展示为准。这笔钱不看攻击记录，买了就按周期扣。选档的起点是你的业务正常带宽——保底档位至少要能顺带消化日常流量里的小规模攻击，别把所有波动都推给弹性计费。

### 弹性防护：最容易产生意外账单的一笔

弹性防护解决“攻击超过保底怎么办”。开启后要设一个弹性上限，攻击流量一旦超过保底，清洗能力自动扩到上限以内；费用按天结算，取**当日攻击流量峰值**对应的档位收费。这个上限就是你的预算闸门，设多大，单日弹性账单的天花板就在哪。

不开弹性行不行？可以，但攻击一旦超过保底，防护会进入封禁状态，业务照样中断。所以对大部分正经业务来说，要决定的只是弹性上限设多少。

### 业务规模：按你接入的业务大小收费

业务规模和防护能力无关，和你转发到高防实例的正常业务体量挂钩，流量越大、并发越高，这一项越贵。业务增长后它要跟着升档，但升档不会自动提升防护能力——两件事分开算，别混为一谈。

## 弹性防护的账单怎么算？看峰值，不看时长

核心规则一句话：按天取当日攻击峰值对应档位，同一天多次攻击只计一次费。攻击打10分钟和打8小时，只要峰值落在同一档，当天费用一样。

举个例子（档位单价以购买页实际展示为准）：假设保底100Mbps、弹性上限5Gbps。周一被打一轮，峰值800Mbps，按对应档位收一天；周二风平浪静，不收费；周三断断续续被打了两个小时，峰值3Gbps，按3Gbps那档收一天。这一周的弹性支出就是两天的费用。

由此能推出一条实用的省钱判断：如果发现弹性费用几乎天天触发，说明保底买低了。天天被打，把弹性费折算成固定支出升保底档位，账单更可控；一年被打两三次的业务则相反，低保底配大弹性上限，比常年扛着高档保底划算。

## 高防IP计费常见问题

### 没有攻击时还收费吗？

收。保底防护和业务规模是预付费项，按购买周期固定扣费，与攻击是否发生无关。弹性防护只在攻击超过保底的当天产生费用，无攻击不扣。

### 弹性防护一天会收几次费？

按阿里云的计费规则，取当日攻击流量峰值对应档位，同一天内多次攻击不重复计费，费用次日结算，具体以官方计费说明为准。对账时把每次攻击的日期和峰值对一遍，对不上的部分提工单问。

### 月付和年付怎么选？

预付费档位两种周期都支持，年付一般有折扣，具体以购买页为准。常见做法是先月付验证配置，跑一两个月确认保底和弹性档位合理后再转年付。

### 攻击造成的弹性费用有保障吗？

国外部分方案内置了成本保护，比如Azure的Network Protection版本。阿里云高防IP的弹性费用按实际攻击计收，预算控制主要靠弹性上限设置——这也是前面反复强调上限别乱填的原因。
